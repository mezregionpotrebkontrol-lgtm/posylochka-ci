# Посылочка — мобильное приложение

Кроссплатформенное приложение (Android + iOS) на [Capacitor](https://capacitorjs.com/) —
тонкая нативная оболочка вокруг рабочего сайта **https://моя-посылочка.рф**.
Весь функционал (регистрация, вход, расчёт стоимости, заказ, онлайн-оплата) работает
через уже готовый сайт внутри приложения — отдельный бэкенд для приложения не нужен.

Такой подход даёт один проект сразу для всех трёх площадок: **Google Play**,
**RuStore** и **App Store** (Android-сборка одна и та же для Google Play и RuStore).

## Структура

```
mobile-app/
  capacitor.config.json   — имя приложения, appId, адрес сайта, цвета заставки
  package.json            — зависимости Capacitor
  resources/
    icon.png              — иконка приложения (исходник 440×440, взят из логотипа сайта)
    splash.png            — экран загрузки
  www/                    — технический пустой заглушка-каталог (Capacitor требует его,
                            но реально приложение сразу открывает ваш сайт по сети)
```

Папки `android/` и `ios/` — сами нативные проекты — не хранятся в репозитории
(их генерирует Capacitor командой `npx cap add`), это стандартная практика. Их
автоматически собирает CI (`.github/workflows/mobile-build.yml`) при каждом
изменении в `mobile-app/`, и выкладывает debug-APK как артефакт — можно скачать
во вкладке **Actions** на GitHub и установить на телефон, чтобы посмотреть,
как приложение выглядит уже сегодня.

## Что уже готово

- Проект собирается и для Android, и для iOS (CI это проверяет при каждом пуше).
- Иконка и заставка сделаны из логотипа сайта.
- Название приложения — «Посылочка», цвет оформления — фирменный тёмно-синий.
- `appId` — `ru.posylochka.app` (можно сменить до публикации, после — нельзя).
- Обработка аппаратной кнопки «назад» на Android (внутри сайта: шаг назад по истории
  браузера внутри приложения, а на самой первой странице — закрытие приложения).

## Почему приложение именно на Capacitor (а не TWA)

Версия 7, которая была собрана как **TWA** (Trusted Web Activity, через Bubblewrap —
по сути открытие сайта в системном Chrome с скрытой адресной строкой), была отклонена
модерацией RuStore с формулировкой «приложение, единственной целью которого является
перенаправление на веб-сайт (WebView)» (п. 8.2 правил модерации RuStore). TWA технически
и есть именно это — обёртка над браузером, без собственного нативного UI.

Capacitor устроен иначе: сайт отображается во **встроенном нативном WebView-компоненте**
(а не в системном браузере), у него никогда нет адресной строки и элементов управления
браузера — это ближе к тому, что требует RuStore. Поэтому проект вернули на Capacitor
(так он и был задуман изначально — см. структуру и CI ниже).

**Важно:** перед повторной отправкой в RuStore обязательно установите debug-сборку
(см. раздел про Actions ниже) на реальный Android-телефон и сравните, как сайт
отображается внутри приложения, с тем, как он выглядит в обычном Chrome на том же
телефоне (масштаб, отступы, растягивание элементов). Ранее именно с рендерингом в
Capacitor WebView были замечания — я не могу проверить это сам без реального устройства,
поэтому прошу подтвердить визуально перед отправкой на повторную модерацию.

## Чего не хватает и что нужно сделать вам

Я не могу создать для вас аккаунты разработчика или опубликовать приложение —
это требует оплаты, подтверждения личности/организации и входа в личные кабинеты
магазинов, которые принадлежат вам. Весь код и сборки готовы, дальше — три
отдельных пути публикации.

### 1. RuStore (проще и быстрее всего — рекомендую начать с него)

1. Зарегистрируйтесь как разработчик на https://console.rustore.ru — у вас уже
   есть ИП (Казаченко Н.Н.), это ускорит регистрацию.
2. Скачайте debug-APK из Actions (см. выше) **либо** соберите release-сборку
   локально (см. раздел «Как собрать release для Android» ниже) — для публикации
   нужен **AAB или подписанный APK**, debug-сборка из CI для магазина не подходит.
3. Залейте карточку приложения: название «Посылочка», описание, иконка (есть
   в `resources/icon.png`, лучше дать версию 512×512 и выше), 3–5 скриншотов
   экрана (можно просто снять с телефона во время теста).
4. Обязательно укажите ссылку на политику конфиденциальности:
   `https://моя-посылочка.рф/privacy-policy.html` (уже готова).
5. **Если это повторная отправка после отказа** — в консоли RuStore загружайте
   новый файл с бо́льшим номером версии (сейчас CI собирает `versionCode 8`,
   `versionName 2.1.0` — это уже больше отклонённой версии 7/2.0.0, менять
   ничего не нужно, если вы не отправляли что-то ещё между делом). В карточке
   приложения в описании можно явно подчеркнуть, что это полноценное приложение
   с собственным оформлением, а не просто обёртка над сайтом.

### 2. Google Play

1. Аккаунт разработчика Google Play — одноразовый взнос **$25**, нужна
   банковская карта и подтверждение личности.
2. Там же, в Play Console, нужна подписанная **AAB**-сборка (см. ниже).
3. Google потребует: политику конфиденциальности (ссылка выше есть), описание
   приложения, скриншоты, значок 512×512, баннер 1024×500, заполненную анкету
   о сборе данных (Data Safety) — честно укажите, что собираются контактные
   данные и паспортные данные для доставки.

### 3. App Store (iOS)

Самый дорогой и долгий путь:

1. Нужен **Apple Developer Program** — **$99/год**, и либо компания с D-U-N-S
   номером, либо аккаунт на физлицо.
2. Для сборки и подписи iOS-приложения в итоге нужен **Mac с Xcode** (или
   облачный Mac, например GitHub Actions `macos-latest`, которые я уже настроил
   в CI — но подписание всё равно требует загрузки ваших сертификатов и
   profile'ей от Apple, которые без вашего участия получить нельзя).
3. После получения аккаунта — создайте App ID в Apple Developer, сертификат
   подписи и Provisioning Profile, затем через Xcode (`npx cap open ios`)
   соберите и загрузите билд в App Store Connect.

## Готовая подписанная сборка для RuStore (уже настроено, нужно включить)

В CI есть job `android-release`, который сам собирает **подписанный release APK**,
готовый к загрузке в RuStore — ключ подписи уже сгенерирован, его файл и пароли
я прислал вам отдельным файлом в чате (`KEYSTORE_SECRETS.txt` и `.keystore`).

**Сохраните эти два файла в надёжном месте (менеджер паролей, зашифрованный архив) —
без ключа вы не сможете выпустить ни одно обновление приложения ни в RuStore, ни
в Google Play.**

Чтобы включить сборку:

1. На GitHub откройте репозиторий → **Settings → Secrets and variables → Actions**.
2. Вкладка **Secrets** → **New repository secret**, добавьте четыре секрета
   (значения — из присланного файла `KEYSTORE_SECRETS.txt`):
   - `ANDROID_KEYSTORE_BASE64` — содержимое файла `posylochka-release.keystore.b64`
     (вставить текст целиком)
   - `ANDROID_KEYSTORE_PASSWORD`
   - `ANDROID_KEY_ALIAS`
   - `ANDROID_KEY_PASSWORD`
3. Вкладка **Variables** → **New repository variable**: имя `HAS_ANDROID_SIGNING`,
   значение `true`.
4. Перейдите во вкладку **Actions** → workflow **Mobile App Build** → **Run workflow**
   (или просто дождитесь следующего изменения в `mobile-app/`).
5. После завершения сборки в Artifacts появится `posylochka-android-release-signed` —
   это и есть файл для загрузки в RuStore (и в Google Play, после получения аккаунта).

## Как собрать release для Android самостоятельно

На своём компьютере (с установленным Node.js и Android Studio):

```bash
cd mobile-app
npm install
npx cap add android
npx @capacitor/assets generate --android --iconBackgroundColor '#0A2472' --splashBackgroundColor '#0A2472'
npx cap sync android
```

Дальше откройте `npx cap open android` в Android Studio:
1. Создайте ключ подписи (Build → Generate Signed Bundle/APK → Create new…) —
   **сохраните этот файл и пароли в надёжном месте**: без него вы не сможете
   выпускать обновления приложения.
2. Соберите **Android App Bundle (.aab)** — это тот файл, который загружается
   и в Google Play, и в RuStore.
